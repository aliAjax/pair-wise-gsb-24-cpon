# hxwl-10 考古探方工作台

遗址探方地层登记、标本交接与全程追溯台。队员与整理员记**同一本台账**（append-only 事件流），
收工后不再出现"两份记录对不上"。

## 业务规则

- **登记**：探方按地层登记开口深度、地层小结、遗迹单位（灰坑/墓葬/房址等）与出土标本；标本自动编号。
- **同层多人协作**：同层有多人时，队员只能对他人记录**补充观察**，不能修改别人的结论；
  自己的草稿可改，一旦**提交交接**即锁定，本人也不能直接改。
- **校正留痕**：资料整理员只能校正已交接的结论 / 标本，**必须填写校正原因**，原记录（before）
  与校正后（after）一并留在台账中，可随时对照。
- **标本交接台**：未交接 → 交接待整理 → 交回入库；按遗址、探方、状态筛选；批量交接/交回。
- **收官闸口**：遗址还有未处理标本（未交接或待整理）时，领队不能宣布收官；已收官可重开。
- **数量派生**：件数全部从台账现算，随登记、交回、校正实时变化，无冗余副本。
- **可续用**：数据保存在浏览器 localStorage，刷新不丢；任意状态都能从事件流完整重建。

## 四个页面

1. **探方登记**：地层卡片（结论 / 补充观察 / 标本 / 校正史），按遗址、探方筛选。
2. **标本交接台**：待办清单 + 批量交接、交回、标本校正。
3. **收官闸口**：各遗址未处理标本统计与收官/重开操作。
4. **追溯台账**：全部操作的时间线（登记、提交、观察、校正、交接、收官），只增不改。

右上角可切换身份（高队长 / 林队员 / 赵队员 / 沈整理员），用于验证不同角色的权限边界。

## 架构（四层分离）

```
src/
├── data/       资料层：领域模型 types.ts、台账事件 events.ts、基础档案与演示数据 reference.ts
├── rules/      规则层：归约 reducer.ts、派生查询 selectors.ts、权限 permissions.ts、命令 commands.ts
├── storage/    保存层：localStorage 事件仓库 store.ts（append-only）
└── ui/         页面层：React 组件、表单、格式化文案、useLedger
```

所有状态变化都先经 `commands`（权限 + 输入校验），通过后生成事件，事件写入仓库并由
`reducer` 归约成页面状态；校验不通过的操作直接抛错，绝不落账。

## 技术栈

React 19 + Vite + TypeScript + CSS，无后端，localStorage 持久化。
